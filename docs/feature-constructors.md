# Feature constructors

`FeatureConstructorsVisitor` generates two constructors for partial Creational, Transitional, and Query features without explicit instance constructors:

- A public parameterless constructor for creating a new request, including through a `new()` constraint.
- An internal `[JsonConstructor]` constructor that restores the payload, causal identity, proposed time, and transitional target from JSON.

The public constructor preserves property initializers. Creational and Query features implicitly call the base parameterless constructor, allowing the framework to create the causal identity and proposed time. Transitional features call `base(target: default)`, initializing the target to a default `Reference<TIdentity>` while creating causal metadata through the base constructor.

For example:

```csharp
namespace Testing.Account.Open;

using Muify.Service;

[Creational<Opened>]
public sealed partial record Open
{
    public Owner Owner { get; init; } = Owner.Unspecified;
}
```

The generated constructors are equivalent to:

```csharp
public Open()
{
}

[JsonConstructor]
internal Open(Guid identity, Owner owner, DateTimeOffset proposed)
    : base(identity, proposed)
{
    Owner = owner;
}
```

`new Open()` retains `Owner.Unspecified`; JSON deserialization restores the supplied owner and causal metadata. Both constructors are generated whether the feature base is declared in source or generated by Muify.

Features with explicit instance constructors, including positional record constructors, remain responsible for their own constructors. Constructors declared in another partial declaration also suppress generation. See [MUIFY05](rules/MUIFY05.md) for the constructor constraint applied to positional aggregates and features.
